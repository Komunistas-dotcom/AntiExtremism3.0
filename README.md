# Сборщик реестра

Первая часть проекта: превращает официальный список экстремистских материалов
в компактный файл базы данных, по которому потом идёт проверка.

Программа проверки будет просто читать этот файл. Благодаря такому разделению
обновление списка **не требует пересборки самой программы** — достаточно
заменить один файл базы.

## Что нужно

Только Python 3.11 или новее. Никаких сторонних библиотек ставить не надо —
это сделано намеренно, чтобы потом собрать один `.exe` без установки.

## Как пользоваться

Скачайте список с сайта Министерства информации и укажите путь к файлу:

```
python -m registry.build data/spisok-ekstremistskix-materialov.doc -o data/registry.db
```

Поддерживаются `.doc`, `.docx`, `.odt`, `.rtf`, `.html`, `.md`. Формат
определяется по содержимому файла, а не по расширению — с сайта нередко
приходит файл с расширением `.doc`, который на самом деле `.docx`.

Посмотреть, что получилось, не создавая файл базы:

```
python -m registry.build data/spisok-ekstremistskix-materialov.doc --stats-only
```

Проверить, что всё работает правильно:

```
python -m unittest discover -s tests -t .
```

Файл базы получается около 6 МБ, поиск одного адреса занимает ~5 микросекунд.

## Про исправление написаний

Главная опасность для такой программы — **ложное «у вас чисто»**. Она возникает,
когда адрес в реестре записан с кириллическими буквами, неотличимыми от
латинских: `vk.соm`, `оk.ru`, `chаnnel`, `раra2022`. Глазом они выглядят
нормально, но для компьютера это другая строка, и совпадение молча теряется.

Сборщик разбирает такие случаи по-разному в зависимости от места:

- **В доменном имени** кириллица недопустима по стандарту, поэтому исправляется
  всегда — включая буквы вроде `к`, которые в остальных местах трогать нельзя.
- **В имени аккаунта** решение зависит от написания. Смешанное (`раra2022`)
  исправляется на латиницу. Целиком кириллическое (`ОбществоГомель`) —
  настоящее название, оно не трогается.
- Когда однозначно решить нельзя (`НАША` кириллицей + `MOBA` латиницей),
  в базу заносятся **оба** варианта: лишняя запись в индексе безвредна,
  а пропущенное совпадение — нет.

Кроме того, исправляются опечатки составителей реестра, найденные сверкой всех
доменов списка с названиями площадок: `twiter.com`, `yotube.com`, `facebok.com`,
`instgram.com`, `tiktok.eom`, `treads.com` и другие.

## Что намеренно не попадает в базу

- **Отменённые решения** — 9 записей. В самом реестре у них уже вычищено
  содержимое, остаётся только слово «Отменено» и реквизиты. Запись сохраняется
  с пометкой, но никаких признаков для проверки с неё не берётся.
- **Домены-посредники** — `apps.apple.com`, `archive.is`, `bit.ly` и подобные.
  Они есть в истории браузера почти у каждого, и как признак дали бы
  ложное срабатывание. Конкретная ссылка внутри такого домена при этом
  сохраняется.
- **Имена аккаунтов, похожие на домен** (`baj.media.by` в Instagram) — не
  дублируются ещё и как отдельный сайт.

## Строение

| Файл | Назначение |
|---|---|
| `registry/ingest.py` | чтение исходного файла любого формата |
| `registry/msdoc.py` | разбор двоичного `.doc` (Word 97-2003) |
| `registry/confusables.py` | таблицы похожих букв и правила их замены |
| `registry/normalize.py` | приведение адресов к единому виду |
| `registry/parse.py` | разбор таблицы реестра на записи |
| `registry/build.py` | запись снапшота в SQLite |

Все находки, на которых построены правила (какие опечатки встречаются, где
кириллица, сколько адресов заканчивается точкой), получены разбором реального
файла, а не предположениями. Тесты закрепляют каждый такой случай.

## Про формат .doc

Файл с сайта министерства — двоичный Word 97-2003. Он разбирается напрямую,
без LibreOffice и вообще без сторонних программ: это нужно и для того, чтобы
всё уместилось в один `.exe`, и чтобы обновление базы не требовало установки
офисного пакета.

Внутри такого файла два слоя: контейнер OLE2 (файловая система внутри файла) и
собственно текст, который лежит не подряд, а фрагментами — часть в UTF-16,
часть в однобайтовой кодировке. Разметка таблицы берётся из самого текста:
конец ячейки в формате Word обозначается символом `\x07`, два подряд — конец
строки. Адреса дополнительно вынимаются из полей гиперссылок, где они
записаны полнее, чем в видимом тексте.

Проверено на настоящем файле (11.8 МБ, 5861 запись): разбор занимает около
секунды и даёт все идентификаторы, которые находились в раннем варианте
списка, плюс новые записи.

# Движок сопоставления

Вторая часть: сверяет следы пользователя с базой реестра.

Посмотреть, как выглядит отчёт (на выдуманных следах):

```
python -m matching.demo data/registry.db
```

## Два разряда совпадений

Они **никогда не смешиваются** в отчёте:

- **Точное** — адрес или идентификатор совпал полностью, при той же площадке
  и том же типе признака. Это факт.
- **Вероятное** — совпало имя, но не всё остальное: например, такое же имя
  значится в реестре на другой площадке. Это повод посмотреть глазами, а не
  готовый вывод.

Разделение принципиально. Ложное срабатывание в такой программе пугает
человека на ровном месте, а свалка из точных и сомнительных совпадений делает
отчёт бесполезным. По той же причине действуют два ограничения:

- **числовые идентификаторы не сравниваются между площадками** — два
  одинаковых числа в разных сетях не значат ничего;
- **имена короче пяти символов** не дают совпадений между площадками.

## Как это защищено от пропусков

Адреса пользователя проходят через **тот же** нормализатор, что и адреса
реестра. Если бы у них были разные правила, одна и та же ссылка превратилась
бы в разные ключи и совпадение потерялось бы. Поэтому ссылка с кириллической
буквой, найденная у пользователя, всё равно совпадёт с чистой записью реестра
— это проверено тестом.

## Отчёт

Отчёт собирается в памяти и показывается на экране. **Сам он никуда не
сохраняется**: перечень собственных следов на диске — это, по сути, готовая
улика, и создавать её незаметно для человека нельзя. Сохранение в файл
возможно только явным действием, и рядом с ним стоит предупреждение.

Если совпадений нет, отчёт прямо говорит, что проверка относится только к
загруженным данным: разделы, по которым выгрузка не делалась, не проверялись.

| Файл | Назначение |
|---|---|
| `matching/observation.py` | приведение следов пользователя к общему виду |
| `matching/engine.py` | поиск следов в реестре, разряды совпадений |
| `matching/report.py` | сборка отчёта |
| `matching/demo.py` | показ на выдуманных следах |

# Проверка браузеров

Третья часть: история и закладки браузеров.

Этот модуль особенный тем, что **не требует ждать выгрузку данных**. Остальные
источники (Meta, TikTok) готовятся от нескольких часов до нескольких суток, а
история лежит на диске и читается сразу — человек получает первый результат в
первую же минуту.

```
python -m connectors.check_browser data/registry.db
```

## Что проверяется

Chrome, Edge, Яндекс.Браузер, Opera, Brave, Vivaldi и Firefox — **все профили
каждого**. У браузера часто несколько профилей («Default», «Profile 1»), и
смотреть надо в каждый.

Из каждого профиля берутся история посещений и закладки. Сверка идёт не только
с перечнем сайтов из реестра (412 доменов), но и с адресами соцсетей: ссылка
вида `t.me/…` или `instagram.com/…` встречается в истории в исходном виде, и
такие следы тоже находятся.

## Про приватность

Браузер держит свою базу открытой, поэтому читается временная копия. Копия
удаляется всегда — в том числе если чтение прервалось ошибкой; на это есть
отдельные тесты. Ничего из истории на диск не записывается: наблюдения
отдаются потоком и живут только в памяти.

Отчёт по умолчанию только показывается на экране. Сохранение в файл — по
явному указанию `--save` и с предупреждением.

## Что сделано против ложных срабатываний

- Повторные заходы на один сайт схлопываются в одну строку отчёта, но число
  посещений сохраняется: оно помогает понять, зашёл человек один раз случайно
  или читал регулярно.
- Домены-посредники (`apps.apple.com`, сокращатели ссылок) в реестр-индекс не
  попадают, поэтому в отчёте их не будет.
- Испорченный или непривычный профиль пропускается молча — проверка остальных
  на этом не срывается.

Проверено на нагрузке: **60 000 записей истории разбираются и сверяются за
1.2 секунды**, и ни одна из 60 000 обычных страниц не дала ложного совпадения.

| Файл | Назначение |
|---|---|
| `connectors/browser.py` | поиск браузеров, чтение истории и закладок |
| `connectors/check_browser.py` | запуск проверки и вывод отчёта |

# Проверка Telegram

Четвёртая часть: подписки, пересылки и ссылки — через защищённый вход
(MTProto), без выгрузки переписки на диск.

```
pip install telethon
python -m connectors.check_telegram data/registry.db
```

Нужен ключ приложения с https://my.telegram.org (API development tools),
он передаётся через `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`.

## Что проверяется

- подписки на каналы, чаты и группы;
- пересылки и ссылки в переписке — **сообщения обеих сторон**;
- «Избранное».

Лайков и реакций Telegram перечислить не даёт, истории просмотров в нём нет.

**Присланное собеседником проверяется наравне с отправленным.** Сообщение из
экстремистского канала, пересланное вам в личку или лежащее в групповом чате,
хранится в вашей переписке — значит, это след. В отчёте отправленное и
полученное помечаются по-разному: это разные действия, и путать их нельзя.

Главное приобретение живого входа — **внутренние числовые идентификаторы**:
393 записи реестра опознаются только по ним, имени канала там нет вовсе.
Вдобавок совпадение по идентификатору переживает переименование канала.

## Безопасность

- сессия живёт только в памяти, файл сессии на диск не пишется;
- по окончании программа выходит из аккаунта — в «Устройствах» не остаётся
  следа стороннего клиента;
- облачный пароль нигде не сохраняется;
- перед входом человеку показывают, что произойдёт, и спрашивают согласие;
- чтение размеренное. Короткую паузу по требованию Telegram программа
  пережидает, а требование ждать долго считает признаком того, что аккаунт
  уже на подозрении: чтение сообщений прекращается, чтобы не довести до
  блокировки. Подписки к этому моменту уже проверены.

## Режимы

| Ключ | Что делает |
|---|---|
| (по умолчанию) | подписки + все сообщения обеих сторон |
| `--subscriptions-only` | только подписки, сообщения не читаются вовсе |
| `--own-messages-only` | только свои сообщения |
| `--quick` | только сообщения со ссылками: во много раз быстрее, но пересылки без ссылки не видны |
| `--limit N` | сколько сообщений смотреть в одном диалоге (по умолчанию 3000) |

| Файл | Назначение |
|---|---|
| `connectors/telegram.py` | разбор данных Telegram в наблюдения, чтение потоком |
| `connectors/check_telegram.py` | вход, согласие, запуск проверки, выход из сеанса |
